# Scenario Review: Session-Only Foundation Cutover

Scope reviewed: `plan.md`, `functional-flow.md`, the foundation scenario-matrix template, architecture/preflight and backlog context, REQ-002 C-010, and current auth/tRPC/schema/env/router source. This is a read-only review; sibling worktrees were not inspected or changed.

## BLOCKER/HIGH

- **Catalog persistence contract is not proven by the proposed schema oracle.** Current root Prisma schema contains only scaffold `Post` plus auth identity models; it has no catalog models. Removing all five models leaves a valid PostgreSQL datasource and generated client, but that alone cannot establish a usable catalog persistence boundary or satisfy C-010. “Catalog-capable” / “structurally possible” can pass while the catalog model contract is absent or incompatible. **Closure:** explicitly distinguish retained infrastructure from an implemented catalog schema; test the post-cutover schema/client against the approved REQ-002 model/interface contract without copying sibling generated output. Record that catalog persistence remains unimplemented if its model contract is intentionally delivered later; do not claim schema validation proves it.

- **No runtime oracle for the anonymous tRPC contract is fixed.** The plan calls a “health procedure” only if one exists, while current `appRouter` registers only `post`; removing it yields an empty router unless another procedure is deliberately provided. S2 also names a removed `post.hello` as optional smoke. HTTP reachability of the catch-all route does not prove a useful anonymous procedure works, context construction is session-free, or router registration is correctly narrowed. **Closure:** make expected post-cutover router surface explicit (including whether empty router is acceptable); exercise an actually registered safe procedure if available, otherwise assert unknown/removed procedure behavior and route transport status without inventing a health API. Assert no session/auth lookup via source/call-graph or an observable spy at a suitable unit boundary, not merely HTTP 200.

- **Worktree safety oracle cannot prove “unchanged” as written.** Plan says compare before/after status, but no captured pre-state is specified; a final clean/changed status alone cannot distinguish this task’s impact from prior user modifications, and status does not prove tracked/untracked bytes unchanged. This matters particularly for generated client artifacts. **Closure:** before any writes, capture sibling status plus content hashes for relevant generated/user-modified files (or rely on an independently retained baseline); after, compare read-only. If a baseline cannot be obtained, report safety as unverified rather than asserting unchanged. Never use checkout/reset/clean operations.

- **Database non-mutation is described as a retrospective command-log assertion, not an enforceable boundary.** No DB target is verified and the contract forbids DB connection; generic command review cannot establish that build/postinstall or a mistakenly selected Prisma command did not connect or mutate. **Closure:** explicitly enumerate allowed Prisma operations (`validate`, `generate`) and disallowed operations; inspect package lifecycle hooks/scripts before execution and confirm generation is schema-local/no DB connection. Record exact executed commands and do not infer “no DB mutation” from absence of a migration command alone.

## MEDIUM

- **Auth endpoint negative test is underspecified.** Testing only `/api/auth/session` does not cover route variants or a stale route handler that responds on another path; route inventory is a source oracle but not proof of no handler at runtime. **Closure:** assert no auth route in the built route manifest/inventory and probe representative `/api/auth/session`, `/api/auth/signin`, and `/api/auth/callback/*` paths; ensure ordinary not-found semantics and no redirects/cookies/auth side effects.

- **Environment scenarios conflate absent auth credentials with absent database configuration.** `src/env.js` currently requires `DATABASE_URL`, and tRPC route imports env validation. Homepage is described as independent of DB, but build/start and API requests may still fail validation without `DATABASE_URL`. **Closure:** run controlled-environment checks with auth variables absent and valid non-secret disposable `DATABASE_URL` configured; separately assert the homepage path does not connect to DB, and document whether `DATABASE_URL` remains globally required at startup. Do not read `.env` or use a real target.

- **Generated-client oracle may false-pass on substring inspection.** “Model names absent” by searching generated files can be defeated by unrelated names/casing or missed because generated artifacts contain stale declarations outside inspected files. Typecheck alone need not instantiate removed delegates. **Closure:** use a bounded contract check against generated Prisma DMMF/model metadata and exported client API, plus a compile-time consumer check that retained Prisma client imports and DB singleton still work; run generation after schema edit, then verify generated output is current in this worktree only.

- **Package removal/recovery side effects lack an integrity oracle.** `pnpm-lock.yaml` changes and `postinstall` runs Prisma generation; a partial install or interrupted generation can leave lockfile/generated client inconsistent. **Closure:** after auth dependency removal, verify lockfile consistency with the repo’s frozen-lockfile install/check and inspect dependency graph for direct/transitive auth package usage; verify generation completion before typecheck/build. Report install/network failure separately from product behavior.

- **Docs completion can contradict the delivery gate.** Plan updates backlog/readiness evidence but does not specify the expected metadata after the cutover. Removing the blocker does not itself prove the foundation is runnable or clear every REQ-001 acceptance condition. **Closure:** add a docs oracle that baseline/backlog/readiness claims align with observed build/launch and architecture evidence; preserve `partial`/`blocked` unless all gate criteria are verified, with no implicit waiver.

## LOW

- **Scenario duplication risks divergent coverage.** `plan.md` and `functional-flow.md` both carry similar but non-identical S1–S6 matrices; the flow matrix omits S6 while the plan has it. **Closure:** designate one canonical matrix or reconcile IDs/coverage so implementers and reviewers do not treat the shorter copy as complete.

- **Recovery is mostly “fix and rerun.”** Build/env failures, Prisma generation failure, and interrupted package update have no explicit restore point or instruction to preserve generated/user changes. **Closure:** state recovery is limited to current-worktree source/lockfile changes, regenerate only from current schema, and never restore or copy generated output from sibling worktrees.

- **No visible behavior assertion for page removal.** A 200 response can still render stale scaffold controls/content, and typecheck cannot detect them. **Closure:** local HTTP body assertion should reject sample-post/sign-in controls and verify the intended anonymous page content, alongside status and no auth env.
## Targeted Closure Review

Re-read `plan.md`, `functional-flow.md`, and this review. Decisions below assess whether each prior finding is closed by the revised plan/flow, not whether implementation has already passed its future checks.

### BLOCKER/HIGH

- **Catalog persistence / C-010 — CLOSED.** Both documents explicitly state the current root schema has no catalog models, preserve PostgreSQL/Prisma only as the permitted future catalog boundary, and forbid claiming C-010 or catalog persistence is implemented. This is an accurate scope boundary rather than a proposed catalog-model compatibility test; none is required for this cutover.
- **Anonymous tRPC contract — CLOSED.** Plan S2 and Task 1 specify the retained catch-all route, intentionally empty root router, no synthetic health procedure, unknown-procedure `NOT_FOUND` HTTP smoke, and route-manifest check. The flow repeats that contract. These are concrete future oracles; they do not imply a registered application procedure.
- **Sibling worktree baseline caveat — CLOSED.** S5 and Task 3 require before/after status plus hashes where feasible and explicitly require reporting integrity as unverified if no stable baseline exists. They prohibit sibling writes and do not turn an unavailable/unstable hash into a clean bill of health.
- **Database command/connection boundary — CLOSED.** S4, Task 2/3 and the flow enumerate `validate`/`generate` as the only allowed Prisma operations, disallow connection, migration/db-push and SQL, require lifecycle-script inspection and exact command accounting, and defer destructive cleanup until target/backup/rehearsal proof. The limit is explicit; no claim of completed execution is made.

### MEDIUM

- **Auth endpoint variants — CLOSED.** S2 and Task 1 name `/api/auth/session`, `/api/auth/signin`, and `/api/auth/callback/discord`, require ordinary not-found behavior without redirect/cookie, and require auth route-manifest absence. The flow specifies no identity/session creation. This is sufficiently representative and testable.
- **Dummy DB environment — CLOSED.** S1/S6 and the flow require auth variables unset while supplying a syntactically valid disposable localhost `DATABASE_URL`; they explicitly retain its shared-validation requirement and separately assert the homepage makes no DB connection. No real `.env` or target is to be read.
- **Generated delegate checks — CLOSED.** S3 and Task 2 require generation after schema removal, inspection of exact removed model/delegate declarations in the generated client, retention checks for datasource/generator/output/URL and DB module, and typecheck. This is a bounded post-generation schema/client oracle, not a substring-only check or a claim based on typecheck alone.
- **Package lifecycle and lockfile integrity — OPEN (residual MEDIUM).** Lifecycle scripts are explicitly to be inspected before package-manager execution, and lockfile updates must use pnpm; however, the plan does not require a frozen-lockfile consistency/install check or explicit dependency-graph verification for residual direct/transitive auth packages. Do not treat lockfile consistency or absence of transitive auth dependencies as established solely by the stated commands.
- **Docs status consistency — CLOSED.** Task 3 specifies which stale claim to replace, retains foundation partial/delivery queued and feature blocked states absent independently satisfied gates, and requires truthful status evidence. S7 separately guards against implying C-010 implementation.
- **Matrix canonicalization — CLOSED.** Plan declares S1–S7 canonical and functional-flow points to that matrix rather than defining a duplicate; IDs and detailed test/environment coverage therefore have one source of truth.

No prior BLOCKER/HIGH item remains open in the revised plan. The sole residual finding is the MEDIUM package/lockfile integrity gap above; these are planned checks, not execution results.
