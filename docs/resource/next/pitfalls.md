# Known Pitfalls & Gotchas (`next@15.5.27`)

| Scenario | Risk or surprising behavior | Required handling | Evidence |
|---|---|---|---|
| Awaiting `params` / `searchParams` in Next.js 15 | Accessing `params.slug` directly without `await` throws a TypeError in Next.js 15 because `params` is a Promise. | Always `const { slug } = await params;` and `const search = await searchParams;` in Server Components and Route Handlers. | [Web] [Next.js 15 Upgrade Guide](https://nextjs.org/docs/app/building-your-application/upgrading/version-15) |
| Calling `headers()` or `cookies()` without `await` | In Next.js 15, `headers()` and `cookies()` are asynchronous and return promises. Accessing them synchronously will fail or throw errors. | Always `await headers()` and `await cookies()`. | [Web] [Next.js 15 Upgrade Guide](https://nextjs.org/docs/app/building-your-application/upgrading/version-15) |
| Catching `redirect()` or `notFound()` in try/catch blocks | `redirect()` and `notFound()` throw internal control flow errors (`NEXT_REDIRECT`, `NEXT_NOT_FOUND`). Wrapping them in `try/catch (err) { ... }` without rethrowing will intercept navigation and suppress it. | Never wrap `redirect()` or `notFound()` in catch blocks, or rethrow `if (isRedirectError(error)) throw error;`. | [Web] [Next.js Docs](https://nextjs.org/docs/app/api-reference/functions/redirect) |
| Uncached `fetch` by default in Next.js 15 | Unlike Next.js 14 where `fetch` requests were cached by default, Next.js 15 defaults `fetch` requests to `no-store` (uncached) unless explicitly specified with `{ cache: 'force-cache' }` or next cache tags. | Explicitly configure caching options (`cache: 'force-cache'` or `next: { revalidate: n }`) when static caching is intended. | [Web] [Next.js 15 Caching documentation](https://nextjs.org/docs/app/building-your-application/caching) |
