# Verified API Surface

Prisma Client's model-specific delegates are generated from `schema.prisma`. The examples below use `user`/`post` generically unless the project-specific schema is called out. Query results and inputs are statically typed from that generated schema; generated model names do not exist until the generate step runs.

| # | API / Symbol | Signature & Options | Description & Return Values | Evidence |
|---:|---|---|---|---|
| 1 | `PrismaClient` | `new PrismaClient(options?)` | Generated client instance with one delegate per model, `$` lifecycle/utility methods. Connects lazily on first query. | [Web] [Client reference](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#prismaclient) |
| 2 | Constructor `datasourceUrl` / `datasources` | `new PrismaClient({ datasourceUrl })`; `{ datasources: { db: { url } } }` | Overrides schema datasource URL at runtime; datasource block key must match schema name. | [Web] [Client reference](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#datasourceurl) |
| 3 | Constructor `log` | `log: ("query" \| "info" \| "warn" \| "error")[]` or `{ level, emit: "stdout" \| "event" }[]` | Configures logs; event mode enables `$on` listeners. Query logs can expose SQL and bound parameters. | [Web] [Client reference](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#log) |
| 4 | Constructor `transactionOptions` | `{ maxWait?, timeout?, isolationLevel? }` | Global defaults for interactive transactions; documented API includes max wait, timeout, and DB-supported isolation level. | [Web] [Client reference](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#transactionoptions) |
| 5 | Model delegates | `prisma.<model>.<operation>(args)` | Generated per model (project schema: `prisma.post`, `.user`, `.account`, `.session`, `.verificationToken`). Each delegate's accepted fields and return shape depend on schema. | [Code] `prisma/schema.prisma`; [Web] [Client reference](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md) |
| 6 | `findUnique()` | `findUnique({ where: ModelWhereUniqueInput, select?, include?, omit? })` | Returns matching record or `null`; `where` requires a unique selector. Same-shape calls may be dataloader-batched. | [Web] [findUnique](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#findunique) |
| 7 | `findUniqueOrThrow()` | `findUniqueOrThrow({ where, select?, include? })` | Returns one record; missing record throws known request error (Prisma v6 behavior, not `null`). | [Web] [findUniqueOrThrow](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#finduniqueorthrow) |
| 8 | `findFirst()` | `findFirst({ where?, orderBy?, cursor?, skip?, take?, select?, include? })` | Returns first matching row or `null`; add deterministic `orderBy` when which record matters. | [Web] [findFirst](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#findfirst) |
| 9 | `findFirstOrThrow()` | `findFirstOrThrow(args)` | Same query shape as `findFirst`; throws if no match. | [Web] [findFirstOrThrow](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#findfirstorthrow) |
| 10 | `findMany()` | `findMany({ where?, orderBy?, cursor?, skip?, take?, distinct?, select?, include? })` | Returns `Promise<Model[]>`; no match returns `[]`. Constrain large result sets with filters and pagination. | [Web] [findMany](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#findmany) |
| 11 | `create()` | `create({ data: ModelCreateInput, select?, include? })` | Inserts a record and returns selected fields; supports nested relation writes. | [Web] [create](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#create) |
| 12 | `createMany()` | `createMany({ data: ModelCreateManyInput \| ModelCreateManyInput[], skipDuplicates? })` | Bulk inserts and returns `{ count }`; top-level createMany does not support nested relation writes. `skipDuplicates` depends on provider. | [Web] [createMany](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#createmany) |
| 13 | `createManyAndReturn()` | `createManyAndReturn({ data, select?, include? })` | Bulk inserts and returns created records on supported providers; confirm connector support and limitations. | [Web] [createManyAndReturn](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#createmanyandreturn) |
| 14 | `update()` | `update({ where: ModelWhereUniqueInput, data: ModelUpdateInput, select?, include? })` | Updates one uniquely selected record and returns it; throws if required target does not exist. | [Web] [update](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#update) |
| 15 | `updateMany()` | `updateMany({ where?, data })` | Updates all matching records; returns `{ count }`. Use an explicit `where` to avoid accidental broad updates. | [Web] [updateMany](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#updatemany) |
| 16 | `delete()` | `delete({ where: ModelWhereUniqueInput, select?, include? })` | Deletes one uniquely selected record and returns deleted projection; throws when required record is absent. | [Web] [delete](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#delete) |
| 17 | `deleteMany()` | `deleteMany({ where? })` | Deletes matching records and returns `{ count }`; omitted filter targets all rows. | [Web] [deleteMany](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#deletemany) |
| 18 | `upsert()` | `upsert({ where: ModelWhereUniqueInput, create, update, select?, include? })` | Finds by unique key and updates, otherwise creates; atomicity/SQL-native upsert depends on Prisma conditions and connector. | [Web] [upsert](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#upsert) |
| 19 | `count()` | `count({ where?, select? })` | Returns number of matching records; `_all`/field counts can count non-null values. | [Web] [count](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#count) |
| 20 | `aggregate()` | `aggregate({ where?, _count?, _avg?, _sum?, _min?, _max? })` | Computes supported aggregates and returns requested aggregate result object. | [Web] [aggregate](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#aggregate) |
| 21 | `groupBy()` | `groupBy({ by, where?, having?, orderBy?, take?, skip?, _count?, _sum?, _avg?, _min?, _max? })` | Groups records by scalar fields; output is generated from selected grouping/aggregate keys. | [Web] [groupBy](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#groupby) |
| 22 | `where` scalar filters | `{ field: value }` or field filter `{ equals?, in?, notIn?, lt?, lte?, gt?, gte?, contains?, startsWith?, endsWith?, mode?, not? }` | Applies type- and connector-aware field predicates; available operators vary by scalar/provider. | [Web] [Filter conditions](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#filter-conditions-and-operators) |
| 23 | Logical filters | `{ AND?: Where[]; OR?: Where[]; NOT?: Where \| Where[] }` | Combines predicates; use `OR` for alternatives and `NOT` to negate conditions. | [Web] [Filter conditions](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#filter-conditions-and-operators) |
| 24 | Relation filters | To-many: `some`, `every`, `none`; to-one: `is`, `isNot` | Filters parent records by related-row conditions; valid operators depend on relation cardinality. | [Web] [Relation queries](https://www.prisma.io/docs/orm/v6/prisma-client/queries/relation-queries.md) |
| 25 | Ordering and pagination | `orderBy`, `cursor`, `skip`, `take` | Sorts and pages results. Cursor pagination uses a unique cursor and is preferable for stable large feeds; order by a unique tiebreaker. | [Web] [Pagination](https://www.prisma.io/docs/orm/v6/prisma-client/queries/pagination.md) |
| 26 | `select` | `{ select: { field: true, relation: { select: ... } } }` | Restricts returned fields and narrows result type; cannot combine top-level `select` and `include` in the same query args. | [Web] [Select](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#select) |
| 27 | `include` | `{ include: { relation: true } }` | Includes relations alongside scalar fields; nested `select` controls nested projection. | [Web] [Include](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#include) |
| 28 | Nested relation writes | `data: { relation: { create, createMany, connect, connectOrCreate, update, upsert, disconnect, delete, set } }` | Mutates related records atomically with parent operation; nested operations are supported only where relation/input shape permits. | [Web] [Relation queries](https://www.prisma.io/docs/orm/v6/prisma-client/queries/relation-queries.md), [transactions](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions.md) |
| 29 | `PrismaPromise` | Delegate call returns lazy `PrismaPromise<T>` (thenable) | Prisma query promise used by array `$transaction`; pass the query promise itself, not an already-awaited result. | [Web] [Transactions](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions.md#sequential-prisma-client-operations) |
| 30 | Array `$transaction` | `$transaction<R>(queries: PrismaPromise<R>[], options?: { isolationLevel? }): Promise<R[]>` | Runs independent Prisma operations sequentially, atomically; preserves array order. | [Web] [Transactions](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions.md#sequential-prisma-client-operations) |
| 31 | Interactive `$transaction` | `$transaction<T>(fn: (tx: TransactionClient) => Promise<T>, options?: { maxWait?, timeout?, isolationLevel? }): Promise<T>` | Executes control flow and queries on transaction-scoped `tx`; thrown error rolls back. Defaults documented: max wait 2s, timeout 5s. | [Web] [Transactions](https://www.prisma.io/docs/orm/v6/prisma-client/queries/transactions.md#interactive-transactions) |
| 32 | `$connect()` | `await prisma.$connect(): Promise<void>` | Explicitly opens the engine/database connection; normally unnecessary because first query connects lazily. | [Web] [Connection management](https://www.prisma.io/docs/orm/v6/prisma-client/setup-and-configuration/databases-connections/connection-management.md#connect) |
| 33 | `$disconnect()` | `await prisma.$disconnect(): Promise<void>` | Closes connections and stops query engine process. Use for finite scripts/shutdown, not after each web request. | [Web] [Connection management](https://www.prisma.io/docs/orm/v6/prisma-client/setup-and-configuration/databases-connections/connection-management.md#disconnect) |
| 34 | `$on(event, listener)` | `$on("query" \| "info" \| "warn" \| "error", callback)` when configured for event emission | Subscribes to configured event logs; query event has timestamp, SQL, params, duration, target. | [Web] [Client reference](https://www.prisma.io/docs/orm/v6/reference/prisma-client-reference.md#log) |
| 35 | `PrismaClientKnownRequestError` | `instanceof Prisma.PrismaClientKnownRequestError`; fields `code`, `meta`, `message`, `clientVersion` | Known query failure; handle by code, e.g. `P2002` unique constraint, `P2025` required record not found, `P2024` pool timeout. | [Web] [Error reference](https://www.prisma.io/docs/orm/v6/reference/error-reference.md#prismaclientknownrequesterror) |
| 36 | Other client errors | `PrismaClientUnknownRequestError`, `PrismaClientInitializationError`, `PrismaClientValidationError`, `PrismaClientRustPanicError` | Distinguish unknown engine failures, startup/connection problems, invalid inputs, and engine crashes. Rust panic requires process/client restart. | [Web] [Error reference](https://www.prisma.io/docs/orm/v6/reference/error-reference.md#prisma-client-error-types) |
| 37 | Client export paths | Root, `edge`, `react-native`, `extension`, `index-browser`, `index`, `wasm`, `runtime/*`, `generator-build`, `sql`, wildcard | Exact package exports include 19 map keys. General Node server/client root is active scope; specialized edge/browser/runtime and generator paths are not recipes for this project. | [Package artifact] [exact package manifest](https://github.com/prisma/prisma/blob/6.19.3/packages/client/package.json) |

## Current project model API

The configured schema declares `Post`, `Account`, `Session`, `User`, and `VerificationToken`, with PostgreSQL datasource, unique/index constraints, and relations. Client output is custom-generated to `generated/prisma`; use the generated artifact after running `prisma generate`. Model-specific inputs/outputs evolve whenever the schema changes.

> API scope is the ORM v6 documented practical surface plus export-map keys; this is not a dump of every generated helper, model-specific type, raw SQL function, or extension API.
