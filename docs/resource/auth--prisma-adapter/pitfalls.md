# Known Pitfalls & Gotchas

| Scenario | Risk or surprising behavior | Required handling | Evidence |
|---|---|---|---|
| Prisma models or fields renamed from adapter's expected names | Adapter directly accesses `prisma.user`, `.account`, `.session`, `.verificationToken` and canonical properties. A model/field rename can break generated delegates or query inputs. | Preserve canonical Prisma model/property names; use `@map` / `@@map` only for physical database naming, or write a custom adapter for different Prisma API shapes. | [Package artifact] [exact implementation](https://github.com/nextauthjs/next-auth/blob/@auth/prisma-adapter@2.11.3/packages/adapter-prisma/src/index.ts); [Auth.js mapping guide](https://authjs.dev/getting-started/adapters/prisma) |
| Missing `User.email` uniqueness or mismatched nullability | `getUserByEmail()` uses `findUnique({ where: { email } })`; the exact adapter fixture declares `email String`, while this project's model declares `email String?`. | Keep `email` unique. Ensure provider data and Auth.js user type agree with nullability; review the project's nullable field against the exact fixture and run typecheck/auth-flow verification before changing it. | [Package artifact] exact source and [schema fixture](https://github.com/nextauthjs/next-auth/blob/@auth/prisma-adapter@2.11.3/packages/adapter-prisma/prisma/schema.prisma); `[Code]` `prisma/schema.prisma:58-66` |
| Missing unique `Account(provider, providerAccountId)` key | `getUserByAccount()` and account unlink operations require generated compound selector `provider_providerAccountId`. | Add `@@unique([provider, providerAccountId])` or compatible composite primary key with same selector fields, and retain exact property names. | [Package artifact] exact source and schema fixture |
| Missing unique session token | Session fetch/update/delete use `where: { sessionToken }`. | Define `sessionToken @unique`; keep required session/user fields and a generated/default id if schema has non-null id. | [Package artifact] exact source and schema fixture |
| Wrong verification token key | One-time use deletes with compound selector `identifier_token`; only the pair uniquely identifies a token. | Define `@@unique([identifier, token])` (or compatible compound primary key) using those names; token use deletes the record. | [Package artifact] exact source and schema fixture |
| Adapter creates user without id | `createUser` deliberately removes `id` to let Prisma generate it. A required id without default causes creation failure. | Use `id String @id @default(cuid())` or another suitable database-generated default. | [Package artifact] exact implementation and schema fixture |
| Adapter-created rows omit schema-added required fields | Account/session/token create calls only pass Auth.js contract fields. Extra non-null columns without defaults cause Prisma constraint errors. | Make custom columns nullable/defaulted or populate them through a custom adapter/appropriate auth callback before database creation. | [Package artifact] exact implementation; [schema fixture](https://github.com/nextauthjs/next-auth/blob/@auth/prisma-adapter@2.11.3/packages/adapter-prisma/prisma/schema.prisma) |
| Treating `undefined` as `null` | Adapter `stripUndefined()` drops undefined properties but preserves explicit `null`; null can intentionally clear nullable columns. | Pass undefined to leave a column unchanged; pass null only when clearing a nullable value is intended. | [Package artifact] exact implementation (`stripUndefined`) |
| Missing cascading relation behavior | User deletion may fail on related rows or leave orphan records depending on FK behavior. | Use explicit relation `onDelete: Cascade` where appropriate and review domain retention requirements before cascading. | [Package artifact] exact schema fixture; project `prisma/schema.prisma` |
| Adding WebAuthn provider without `Authenticator` model | The adapter returns authenticator methods that call `prisma.authenticator`; current project schema has no such generated delegate. | Add exact compatible `Authenticator` fields/unique keys/relation, migrate, regenerate, and only then enable WebAuthn. | [Package artifact] exact implementation and [schema fixture](https://github.com/nextauthjs/next-auth/blob/@auth/prisma-adapter@2.11.3/packages/adapter-prisma/prisma/schema.prisma); `[Code]` `prisma/schema.prisma:4-75` |
| Reusing expired or consumed verification token | `useVerificationToken` is destructive and one-time. It maps Prisma `P2025` to `null` if token is already absent; other errors propagate. | Treat `null` as invalid/consumed token and do not swallow unrelated database failures. | [Package artifact] exact implementation; [Prisma P2025](https://www.prisma.io/docs/orm/v6/reference/error-reference.md#p2025) |
| Assuming adapter methods are wrapped in one application transaction | Each adapter operation invokes its own Prisma query; an auth flow can consist of multiple separate operations. | Keep DB constraints correct and design custom multi-write invariants explicitly; don't assume cross-method transactionality. | [Package artifact] exact implementation |
| Auth.js core versions differ between adapter and NextAuth | Adapter 2.11.3 depends on core 0.41.3; NextAuth beta.25 depends on core 0.37.2. Duplicate type contracts can create assignment/type differences and newer methods may be unknown to older core. | Align versions when choosing dependencies, or run an explicit typecheck/runtime auth-flow test before relying on this combination. Do not silently force a transitive override. | [Package artifact] manifests; `[Code]` `pnpm-lock.yaml:925-946,1413-1416` |
| Provider-specific account data omitted from schema | Provider-specific OAuth token fields may be needed for refresh flows (e.g., provider supplies refresh-token expiry); dropping them loses functionality. | Compare each enabled provider's token payload with `Account` fields and add compatible optional fields; generate/migrate afterward. | [Code] `src/server/auth/config.ts:33-46` notes provider-specific fields; [Adapter schema fixture] |
